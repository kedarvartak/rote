### Changed
- Give the benchmark one statistics kernel. `wilsonInterval` was implemented five times and `mulberry32` twice, alongside two more `reductionRatio` copies that bypassed `stats.reduction`, and they had drifted: two Wilson copies had lost the `attempts < 1` guard, so a zero-attempt cell rendered `[NaN, NaN]` as though it were a measurement, and the head-to-head `reductionRatio` clamped with `Math.max(0, ...)`, so a cell where Rote spent *more* than its baseline published as "0% reduction" instead of a regression. All of them now come from `stats.ts`, `reduction` is signed, and the seeded RNG is pinned by a test vector because the published claim is a bootstrap's lower bound and the stream is part of the result. No certified number changes: the two RNG variants were verified identical for 2,000,000 draws (the bootstrap uses 10,000) and all 251 existing bench tests pass unchanged (#215).
- Fail closed when a fingerprint input cannot be canonicalised: `canonicalStringify` raises `NonCanonicalValueError` (naming the path) for a `Date`, `Map`, `Set` or class instance, a non-finite number, a bigint, function or symbol, and an `undefined` array element. `JSON.stringify` maps each of those onto some *other* value's image — a `Date` and a `Map` both to `{}`, `NaN` and `Infinity` both to `null` — so approximating one would hand two different environments the same fingerprint, and sacred invariant 3 short-circuits on that hash before any fuzzy matching. An `undefined` object property is still dropped, since in JSON that is the same statement as an absent key. No caller in the repo passed such a value; this closes the shape of the failure, not a live one (#210).
- **P2**: Carry the executor's terminal exit code through the fallback. A warm replay that failed was reported as `replay_failed` plus a sentence, discarding the classification #203 added, so a caller could not tell a failed `verify` (the playbook is wrong for this state) from a failed checkpoint write (the machine is). `rote run` now prints `fallback: <reason> [<code>] (<detail>)`, `BrowserTaskResult` gains `fallbackCode` and the warm-path `failureCode`, the environment gate and a replay that throws are classified too, and a replay that fails without a code is named `REPLAY_UNCLASSIFIED` rather than folded in with the rest. The sacred baseline invariant is now driven by `EXECUTOR_EXIT_CODES`, so a new exit code with no fallback coverage fails the suite (#206).

### Fixed
- Stop a badly timed crash from making an append-only log permanently unreadable. The playbook library index, the site-memory partitions and the continuation checkpoints each decided "interrupted write or corruption?" by testing whether the line ended in `}`, which is wrong in both directions: `{"a":{"b":1}` ends in a brace and is a torn fragment, so a crash truncating there made every later read raise — losing a site's tier-2 memory, the warm-replay library, or the checkpoints a stranded task resumes from — while genuine garbage that happened not to end in a brace was skipped without a word. All four logs now share one rule in `@rote/core` (`parseJsonl`, `isTruncatedJson`): a line that is a prefix of some valid JSON is an interrupted write, anything else raises `JsonlLineError`. Fragments are recoverable anywhere in the shared logs, because the next append writes past them rather than editing them away, and only at the end of a run's trajectory, which nothing appends to after the run dies (#216).
- Stop losing a `__proto__` key from a recorded event (#208). `writeTrajectoryJsonl` wrote it and `parseTrajectoryJsonl` returned an event without it, because Zod rebuilds a record by assignment and that one key sets a prototype instead of defining a property — data loss, not prototype pollution. Both directions now raise `TrajectoryKeyError`; the reader checks before the schema, which would otherwise report a perfectly valid event that is quietly missing a field. The live recorder appends with `JSON.stringify` directly, so nothing can end a run in flight. The round-trip property test now generates the key again and asserts the whole invariant: an event either reads back exactly or is refused (#214).
- Make observation, dispatch and verification agree on whether an element is visible and on what a selector names. `isElementVisible` existed three times and `matchesSelector` twice, and both had drifted in the same direction — the copy furthest from dispatch was the most permissive. Verification knew nothing of `opacity:0`, `data-rote-visible="false"` or `input[type=hidden]`, so a fully transparent success banner satisfied a `text_visible` check; dispatch matched `opacity:0` as a substring, so a translucent `opacity:0.5` control vanished from the selectors and input values a replayed step reports back; and only one of the two selector matchers honoured `data-rote-selector`. One rule now lives in `@rote/perception` (`isElementVisible`, `matchesElementSelector`), and a new sacred invariant drives all four layers over a corpus of the exact cases they used to disagree on (#213).
- Treat a template parameter inherited from `Object.prototype` as unbound. The binding check was `name in bindings`, which walks the prototype chain, so `{{toString}}`, `{{constructor}}`, `{{valueOf}}`, `{{hasOwnProperty}}`, `{{isPrototypeOf}}` and `{{__proto__}}` read as bound on *every* bindings object and rendered `Object.prototype`'s member instead of raising `UnboundParamError` — a function value for a sole reference, or the text `function toString() { [native code] }` spliced into a longer string and dispatched into the page. The check is now `Object.hasOwn`, which is what the function's own contract already promised: an unbound param is never silently rendered (#212).
