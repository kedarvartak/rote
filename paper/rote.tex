\begin{abstract}
% ~150--200 words. Claim, mechanism, evidence, caveat.
Browser agents built on large language models spend most of their budget re-reading pages they have already seen and re-deriving actions they have already taken. Every agent harness \emph{has} memory; almost none \emph{manages} it. We present Rote, a memory manager that treats the context window as a managed resource---with an explicit budget, an eviction policy, a layout contract that keeps a cache-stable prefix, and a trust gate on everything re-admitted---across three tiers: working memory within a run, episodic memory across runs of the same task, and semantic memory across tasks on the same site. Rote distills recorded trajectories into value-free, contract-gated playbooks; matches new tasks against them with a fail-closed matcher; and replays with zero model calls until a versioned \emph{action contract} detects that a same-looking control changed its behavior, at which point it falls back to the plain agent before any dispatch. On a frozen enterprise-style benchmark, Rote reduces logical input tokens by 83.1\% (95\% CI 82.1--83.9\%) and billed cost by 68.2\% at exact-oracle parity with a strong open-source baseline, and its offline next-action predictor reaches 99.4\% kind+target accuracy over 1{,}520 warm steps. All mechanisms fail closed: 0/90 silent failures were observed under selector drift, destructive decoys, and ambiguity. \textbf{[TODO: replace with numbers from the billed learning-curve campaign once run.]}
\end{abstract}

\section{Introduction}
\label{sec:intro}

A browser agent that files the same expense report every week pays for it every week as
if it were the first time: it re-reads pages it has seen hundreds of times, re-derives
actions it has taken hundreds of times, and re-spends the tokens both cost. The waste
compounds inside a single run, too --- the standard harness is a chat transcript in
which every observation stays resident, so an agent's prompt grows with everything it
has ever seen rather than with anything it still needs. Every agent harness \emph{has}
memory in this weak sense. Almost none \emph{manages} it: nothing decides what deserves
to stay in the window, nothing turns a successful run into a cheaper next run, and ---
most dangerously --- nothing gates what remembered material is trusted enough to act on.

The last gap is the one that makes the first two hard. Reusing memory on the web is
unsafe by default: a control that looks identical to last week's can have changed its
behavior (the same button now purges instead of saves), a page that looks like the
target can be its destructive twin, and a procedure learned on staging must never fire
on production. A memory system that ignores these failure modes converts each of them
into a mistake repeated at volume. We contend this is why harnesses append and hope:
without trust machinery, managed memory is a liability.

We present \textbf{Rote}, a memory manager for browser agents that treats the context
window as a managed resource --- with a budget, an eviction policy, a layout contract,
and a trust gate on everything re-admitted --- across three timescales: \emph{working}
memory within a run, \emph{episodic} memory across runs of one task, and
\emph{semantic} memory across tasks on one site. Rote is a complete harness, not
middleware: eviction, diffing, cache-stable layout, compaction, distillation, matching,
replay, prediction, and model routing all live inside the loop, because a layer at the
tool boundary can advise but cannot restructure what the model sees.

Our contributions:
\begin{itemize}
\item \textbf{The context window as a managed resource} (\S\ref{sec:tier0}): an
  eviction policy that keeps what the agent \emph{did} rather than what it \emph{saw}
  (with a typed, honest failure when an evicted observation is needed), observation
  diffing, a cache-stable layout, and scheduled compaction --- together cutting logical
  tokens 83.1\% and billed cost 68.2\% at exact-oracle parity with a strong baseline.
\item \textbf{A gated learning loop} (\S\ref{sec:tier1}--\ref{sec:gates}): record
  $\rightarrow$ distill $\rightarrow$ match $\rightarrow$ replay, where playbooks are
  value-free and parameterized, replay costs zero model calls, and four fail-closed
  gates --- environment fingerprint, matcher, per-step action contract, authoritative
  outcome evidence --- bound the cost of being wrong. Under 90 adversarial drift
  attempts, zero ended silently wrong.
\item \textbf{Judgment stays out of memory}: a distiller that \emph{refuses} --- a
  value matching no declared parameter, or a run that cannot teach a declarative
  verification, aborts distillation --- so a memorized procedure can never freeze a
  per-instance decision (a triage category, a credential) into a replay.
\item \textbf{Measurement discipline} (\S\ref{sec:setup}): exact external oracles,
  contemporaneously paired pinned baselines, a token metric that provider caching
  cannot inflate, and a benchmark containing its own trap --- a lookalike task that a
  correct system must \emph{refuse} to replay.
\end{itemize}

\section{Related work}
\label{sec:related}

\paragraph{Web and browser agents.} Benchmarks such as WebArena
\citep{zhou2023webarena}, Mind2Web \citep{deng2023mind2web}, and OSWorld
\citep{xie2024osworld} established realistic web-task evaluation, and agents like SeeAct
\citep{zheng2024seeact} and WebVoyager \citep{he2024webvoyager} established the
observe--decide--act loop over accessibility trees and screenshots. Open-source harnesses
--- Browser Use \citep{browseruse2024}, Stagehand \citep{stagehand2024}, and Skyvern
\citep{skyvern2024} --- ship this loop as a product, typically as a chat transcript in
which every observation stays resident. Our work is complementary to all of these: Rote
is not a new policy or a new benchmark but a management layer for the resource every such
agent already spends.

\paragraph{Agent memory.} MemGPT \citep{packer2023memgpt} introduced OS-style paging
between context and external storage for dialogue; CoALA \citep{sumers2023coala}
organizes agent memory conceptually into working, episodic, semantic, and procedural
stores. Experience-reuse systems learn from prior trajectories: Reflexion
\citep{shinn2023reflexion} stores verbal self-feedback, Voyager \citep{wang2023voyager}
grows a code skill library in Minecraft, Synapse \citep{zheng2023synapse} retrieves
exemplar trajectories as few-shot prompts, and Agent Workflow Memory
\citep{wang2024awm} induces reusable workflows from successful runs and injects them
into the prompt. Rote differs on two axes. First, reuse is \emph{executable and gated},
not advisory: a matched playbook replays deterministically with zero model calls, but
only behind an environment fingerprint, a fail-closed matcher, a per-step action
contract, and authoritative outcome evidence --- prior systems inject remembered
guidance and let the model decide, which cannot bound the cost of being wrong. Second,
stored memory is \emph{value-free by construction}, so credentials and form contents
recorded in one run cannot leak into another. Knowledge-memory services such as Mem0
\citep{mem0:2024} and Zep \citep{zep2025} store facts about users and domains; Rote
stores procedures and site behavior, and the two compose.

\paragraph{Managing the window itself.} Provider-side prompt caching
\citep{anthropic2024caching, openaicaching2024} discounts a repeated prefix but leaves
deciding \emph{what} stays in the window to the harness; context-compression methods
\citep{jiang2023llmlingua} shrink a prompt lossily. Rote treats these as levers inside a
policy: an eviction rule chooses what survives, a layout contract keeps the surviving
prefix cache-stable, and compaction folds history under a budget --- compression shrinks
a step, while Rote declines to run it.

\paragraph{Learning from demonstration.} Distilling a recorded trajectory into a
parameterized program echoes programming-by-demonstration for the web
\citep{leshed2008coscripter} and trace-based macro induction \citep{li2010sikuli}. Rote's
distiller differs in what it refuses: a value that matches no declared parameter aborts
distillation, and a run whose verifier cannot state declarative checks cannot teach a
\texttt{verify} --- refusals that exist so a memorized procedure can never be more
confident than the evidence that produced it.

\section{Rote: the memory spine}
\label{sec:design}

Rote is organized around a single reading of the agent loop: the context window is
memory, and memory needs a manager --- a budget, an eviction policy, a write path, and a
trust gate on everything re-admitted. The operating-system analogy is exact and we treat
it as a design discipline rather than a metaphor: the context window is RAM, observations
are pages, dropping them is eviction, diffing is delta encoding, the provider prompt
cache is a cache level, compaction is garbage collection, a distilled playbook is a
cached compiled program, and site memory is the persistent store. Each of these has a
manager in an operating system; none has one in a shipping browser agent, which appends
to a transcript and hopes. Rote supplies the manager at three timescales: \emph{working}
memory within a run (\S\ref{sec:tier0}), \emph{episodic} memory across runs of one task
(\S\ref{sec:tier1}), and \emph{semantic} memory across tasks on one site
(\S\ref{sec:tier2}). The trust gates (\S\ref{sec:gates}) are not a fourth tier but the
precondition for all three (Figure~\ref{fig:architecture}): memory that might be wrong is worse than no memory, because
reuse without verification is a machine for repeating a mistake at volume.

A second commitment follows from the first: control flow should be deterministic. A
successful run tangles together \emph{what to do} (the procedure) and \emph{what to
decide} (the content). Rote untangles them --- the procedure becomes a deterministic,
replayable artifact, and the model is invoked only where genuine judgment lives: binding
parameters, filling slots, and repairing broken steps.

\subsection{Tier 0: working memory as a budgeted resource}
\label{sec:tier0}

The dominant cost in a transcript-style agent is quadratic. With per-step action records
of $\sim$35--40 tokens, step $n$ costs $c + 40n + \mathit{obs}$, so an $n$-step run
carries a $40\cdot n(n+1)/2$ term; if every observation also stays resident at 5--40K
tokens each, step 20 is a 100--800K-token prompt. Rote's context assembler enforces a
layout contract with four segments --- a constant instruction prefix, a constant page
header, a linearly growing action history, and the \emph{current} observation only ---
and applies four levers against the curve. (1)~\textbf{Observation eviction}: prior
observations are dropped; the model recalls what it \emph{did}, not what it \emph{saw}.
This is a real trade: a task whose answer lives in an evicted observation cannot be
completed, so after first omission the context marks the recall boundary and instructs
the planner to return a typed \texttt{recall\_unavailable} failure instead of guessing;
independent verification separately rejects fabricated answers. The task still fails ---
the protection is that it fails honestly. (2)~\textbf{Observation diffing}: the current
observation is served as a delta against a grounded base; across 849 real-page
certification diffs the median delta is 24 characters, a 99.6\% median reduction.
(3)~\textbf{Cache-stable layout}: the prompt is ordered $[\text{stable
prefix}][\text{append-only history}]$ and routed by a deterministic immutable-prefix
cache key, so the surviving prefix is billed at the provider's cached rate; measured on a
25-step cell this cuts billed cost by 20.5\%. (4)~\textbf{Scheduled compaction}: past a
budget threshold the action history is folded into a versioned summary with the recent
suffix kept verbatim, holding visible history $O(1)$ in steps; a 60-transition
single-page-application session sustains this with at most 31 visible actions and three
compaction boundaries.

\subsection{Tier 1: episodic memory --- record, distill, replay}
\label{sec:tier1}

Every run is recorded to an append-only, crash-safe event log (one fsync per event, large
results spilled to content-addressed blobs). The \emph{distiller} converts one successful
recorded trajectory into a playbook: a parameterized, value-free procedure in which
concrete user inputs are lifted to named parameters, and every step carries the target's
structural identity, its \emph{action contract} (\S\ref{sec:gates}), and a learned
verification derived from the recorded evidence class of the original success. Values
never survive distillation --- credentials and form contents are replaced by parameter
references at distill time, so a playbook can be shared or inspected without leaking a
recorded secret. Replay executes the playbook deterministically with zero model calls,
asserting each step's expectations before and after dispatch; on our benchmark tasks a
recorded run distills and replays end-to-end with zero edits and zero tokens. A failed
assertion never degrades into a guess: the run stops, the failure is classified, and the
system falls back to the plain agent with the classification attached.

\subsection{Tier 2: semantic memory --- site memory and the brief}
\label{sec:tier2}

Across tasks on one site, Rote accumulates \emph{value-free} records keyed by a stable
page digest: selector maps, form field semantics, page-transition edges, settle-time
priors, and a closed vocabulary of site quirks. Value-freedom is enforced structurally
--- record schemas have no field that can hold page content, and an invariant test
derives site memory from a live run and asserts no user value appears anywhere in the
store. At run time the relevant records are rendered into a \emph{site brief}: a
hard-capped, deterministic block placed in the cache-stable prefix and framed as
advisory hints, never as instructions the planner must obey. Every run records the
brief's size and how many of its hinted identities were actually used, so the brief's
utility is measured rather than assumed.

\subsection{Trust gates}
\label{sec:gates}

Four gates stand between stored memory and a dispatched action, ordered from cheapest to
most specific. (1)~\textbf{Environment fingerprint} (hard gate): a structural fingerprint
of the environment must match exactly before any fuzzy matching is attempted; a playbook
learned on a staging host can never fire on production. (2)~\textbf{Matcher} (fail
closed): a new task selects a playbook only if intent similarity clears a threshold
($\tau = 0.8$) with a minimum margin over the runner-up (0.05), every required parameter
binds, and every content-bearing token of the task's intent is covered --- the coverage
requirement was added after a near-miss in which a destructive lookalike task scored
0.82 against a benign playbook. On any ambiguity the matcher declines and the plain
agent runs. (3)~\textbf{Action contract}: each step stores a versioned, value-free
contract of the control it dispatches --- element role, input modality, and the
observed effect class of activation. Before dispatch, the live control's derived
contract must equal the stored one; a same-looking button whose behavior changed (a
destination change, a method change, a purge action behind a familiar label) stops the
replay with a typed mismatch and zero dispatches, while cosmetic drift, selector
renames, and wrapper insertion replay normally. (4)~\textbf{Outcome evidence}: task
success is asserted only against authoritative, freshness-bound evidence tied to the
task subject --- a harness's own conclusion, stale evidence, or evidence about a
different subject all fail typed.

\subsection{Predictor and model routing}
\label{sec:routing}

With memory managed, two further systems spend the remaining model budget deliberately.
The \emph{predictor} is an ensemble of trace matching against prior runs and a learned
transition model, emitting a next-action prediction with a monotone confidence score. It
runs in \emph{shadow mode}: predictions are recorded and scored on every run but never
dispatched, because offline confidence is not yet calibrated on live pages
(\S\ref{sec:results-predictor}). The \emph{router} sends confident steps to a routine
(smaller) planner model and escalates to the frontier model on planner output errors or
target repair, preserving the never-worse-than-baseline invariant; escalation spend is
accounted separately so routing economics are measurable. Every model call in the system
carries a source tag through a single client wrapper (\S\ref{sec:invariants}), so all
reported token numbers decompose exactly by subsystem.

\section{Experimental setup}
\label{sec:setup}

\paragraph{Benchmark.} We evaluate on a frozen benchmark of enterprise-style browser
tasks. B1--B3 are deterministic fixture tasks (navigation, an eight-field vendor
registration form with an exact external completion oracle, and a search/extract task);
B4 is a long-session budget task; B5 is a deterministic drift suite over the B2 form
(selector renames, wrapper insertion, destructive decoys behind stale selectors, and an
adversarial ambiguity class); B6 is a false-match trap --- a page that \emph{looks} like
the B2 form but posts to a vendor-offboarding endpoint, testing whether learned
procedures fire on lookalikes. A separate real-page family uses a digest-pinned WordPress
administration instance whose measured page weight is stable to zero range across 15
fresh sessions, with task cells from 9 to 25 steps. Success is never self-reported: every
task binds an exact external oracle (database row, server-side counter, or exact field
set), and harness-success/oracle-failure cases are counted against the harness.

\paragraph{Baseline.} The primary baseline is Browser Use, an open-source browser agent
harness, version-pinned by source commit and wheel digest, run unmodified and
contemporaneously paired with Rote (alternating attempts, same provider, model, viewport,
and fixture generation) on the same oracles. We additionally attempted to qualify three
other harnesses; per our pre-registered qualification protocol we \emph{stopped} each
before certification spend rather than report a ranking from unreliable cells: one
achieved 1/6 exact cold successes with incomplete receipts, one produced 24/24 fallback
executions with 0/28 complete provider receipt sets, and one (vision-driven) timed out in
6/6 frozen attempts. We report these stops as scope limits, not comparative results.

\paragraph{Metrics.} \emph{Logical input tokens} are uncached input plus cache reads plus
cache writes, so provider-side caching cannot masquerade as token reduction; billed cost
uses published provider rates and measured cache buckets; latency is wall-clock per task.
Intervals are matched-pair bootstrap (10{,}000 resamples, 95\%); failed and abandoned
attempts stay in the success denominator. All protocols are frozen before collection and
before totals are inspected.

\subsection{Warm-run economics}
\label{sec:results-econ}

On the exact-oracle B2 cell, paired contemporaneously against pinned Browser Use with
18/18 successes on both sides and zero harness-success/oracle-failure cases, Rote uses
8{,}353 mean logical tokens per task against the baseline's 49{,}324 --- a reduction of
\textbf{83.1\%} [82.1--83.9\%]; billed cost falls \textbf{68.2\%} [66.3--69.9\%]
(\$0.0038 vs.\ \$0.0120 per task) and latency \textbf{43.6\%} [39.0--48.1\%]. On the
real-page WordPress curve (15 matched repetitions per cell, all 150 runs passing the
independent database verifier), Rote's cumulative logical-input growth is 37.2\%
[35.6--38.8\%] slower than the baseline's, with per-cell reductions rising from 14.3\% at
9 steps to 26--28\% at 17--25 steps --- the gap widens with depth, which is the signature
of managing the history term rather than the constant (Figure~\ref{fig:curve}). Exact-prefix cache routing
contributes a measured 20.5\% billed-cost cut on the 25-step cell over the same layout
without deterministic routing.

\subsection{Drift and safety}
\label{sec:results-safety}

The B5 drift certification runs 90 deterministic real-Chrome attempts across four
recoverable mutation classes and one adversarial ambiguity class: 72/72 recoverable
attempts finish with exact oracle success after deterministic semantic repair (zero
repair tokens --- repair here is structural target re-resolution, not a model call), the
18 ambiguity attempts all decline into clean fallback, and \textbf{0/90} attempts end
silently wrong (95\% upper bound 4.1\%). Stale selectors pointing at destructive decoys
never touch the decoys. The action-contract gate extends this to \emph{behavioral} drift:
against six versions of the same page, cosmetic redesign, id renames, and wrapper
insertion replay normally, while an input-to-textarea change, a changed destination, and
a POST-purge control behind a familiar label each stop with a typed contract mismatch and
\emph{zero dispatches} --- an ungated contrast run demonstrates the purge counter moving,
so the gate is load-bearing. On the B6 lookalike, the matcher never selects the benign
playbook for offboarding-shaped tasks, and even a forced replay dispatches no submit.

\subsection{Learning across runs}
\label{sec:results-learning}

Recording one successful run of B1 or B2 and distilling it yields a parameterized
playbook that replays end-to-end in real Chrome with zero model calls and zero human
edits; recorded values and credentials do not survive into the playbook. The distilled
playbook survives selector renames and stops before a contract change. Multi-session
continuation resumes an interrupted controlled workflow across two real browser/process
restarts to the exact three-event oracle with no repeated dispatch, while fingerprint,
principal, procedure, binding, stale-evidence, and diverged-state mismatches each stop
with zero dispatches; interrupted checkpoint writes recover without in-place edits.

\subsection{Predictor (shadow mode)}
\label{sec:results-predictor}

Offline, over 1{,}520 warm steps from 189 recorded fixture runs under leave-one-run-out
evaluation, the trace+transition ensemble predicts the next action at \textbf{99.4\%}
kind+target accuracy (Wilson 98.9--99.7\%); on 2{,}805 live WordPress steps the
kind-only rate is 96.5\%. Thresholding at confidence $\geq 0.9$ covers 62.4\% of steps at
99.8\% precision. However, confidence is \emph{under-calibrated} on the fixture corpus
(scores near 0.33 realize $\approx$99\% accuracy), so predictions are never dispatched (Figure~\ref{fig:predictor}):
the predictor runs in shadow mode on every product run, accumulating the live calibration
that acting on a prediction would require.

\subsection{Long sessions}
\label{sec:results-sessions}

Under the frozen compaction policy, 15/15 fresh real-Chrome runs complete a
60-transition single-page-application session with planner-visible history bounded at 31
actions (three compaction boundaries), 100\% of post-bootstrap observations served as
diffs against a stable document token, zero document changes across 60 route pushes, and
stale remounted identities rejected before dispatch.

\section{Limitations}
\label{sec:limitations}

\textbf{Fixture-weighted evidence.} Most safety results (drift, contracts, false-match,
judgment gate) are certified on frozen synthetic fixtures in real Chrome; the real-page
evidence covers one site family (a digest-pinned WordPress instance). The fixtures were
built adversarially --- the benchmark contains its own traps --- but breadth across
production sites is unproven. \textbf{Partial baseline coverage.} One baseline survived
our qualification protocol; three others were stopped before certification spend rather
than reported from unreliable cells, so our comparative claims are against a single
(strong, pinned) harness. \textbf{The learning-loop economics are mechanism-complete
but not yet campaign-measured}: cold-to-warm reduction with automated distillation,
site-brief generalization, and routine-model routing all have built mechanisms and
per-run telemetry, but their end-to-end numbers await the billed campaign and are
marked TODO. \textbf{The predictor never acts}: its confidence is under-calibrated on
fixtures, so it ships in shadow mode by design; speculation is future work gated on
live calibration. \textbf{Scope}: Rote stores procedures and site behavior, not user
knowledge; multi-user permissioning and credential lifecycles are outside this paper.

\section{Conclusion}
\label{sec:conclusion}

Rote reframes the browser-agent efficiency problem as a memory-management problem: the
context window is the scarce resource, and budget, eviction, layout, compaction,
distillation, and trust gates are its manager. The reframing pays twice. Economically,
managing the window cuts logical tokens by 83.1\% at exact-oracle parity, and the gap
\emph{widens} with task length because the policy attacks the growth term, not the
constant. Behaviorally, the trust gates turn memory's failure mode from silent
repetition into priced fallback: across every adversarial suite we built --- behavioral
drift behind an identical-looking control, a destructive lookalike page, a
judgment-dependent decision a playbook must not freeze --- the system's worst observed
outcome is paying the cold price it would have paid anyway. Memory that cannot be
trusted is declined, not deployed. We believe this manager-plus-gates shape, not any
single mechanism in it, is the transferable result.

\subsubsection*{Reproducibility statement}

All mechanisms are exercised by deterministic suites that run in CI without a model or
provider key, including the sacred invariant suites for every fail-closed gate claimed
in this paper. Every measured number cites a frozen, numbered test record; each record
states its protocol (fixture versions, model, pinned baseline source and wheel digests,
pairing, bootstrap procedure) precisely enough to be re-run and disagreed with, and the
raw per-run data (trajectories, provider receipts, summary JSON) ships alongside.
Figures are regenerated deterministically from those frozen data files by a committed

\section{Action-contract fields and drift boundary}
\label{app:contract}

A step's recorded contract carries: verb; target role, accessible name, stable
identity, and context hash; affordance (control class from a closed enum, input type,
enter behavior, destination hash, form method, draggability); a safety class; observable
preconditions; and optionally the authoritative evidence class the step must produce.
The schema is strict --- unknown fields, and therefore captured values, fail to parse.
Compatibility is an explicit matrix, not similarity: cosmetic drift, selector renames,
and wrapper insertion are compatible; a changed control class (input $\rightarrow$
textarea), a changed destination hash, or a safety escalation (navigation $\rightarrow$
mutating) are mismatches that stop replay before dispatch with a typed error naming the
field family, never the values.
